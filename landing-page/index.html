Video Auto-Labeling Pipeline

An automated backend pipeline for video segmentation — using visual boundary detection, AI transcript classification, and AWS serverless architecture — paired with an archivist-facing Segmentation Review Platform for human validation. Configurable for any video type: broadcasts, lectures, sports, podcasts, and more.

AWS Lambda Step Functions OpenCV Bedrock Claude React Amplify

Unlocking Video Archives at Scale

Thousands of hours of video sit in archives every year — unsearchable, unlabeled, and invisible to researchers who need them most. The Video Auto-Labeling Pipeline changes that. Built at the intersection of computer vision, large language models, and cloud-native architecture, this backend system watches video so humans don't have to — automatically identifying segment boundaries, classifying content types, and producing structured metadata ready for discovery platforms, citation tools, and scholarly research.

What once took trained archivists days of manual review now happens in minutes, at a fraction of the cost. The pipeline processes an hour of video for under $2 — detecting visual transitions, transcribing speech, and using AI to segment and label every moment. Results flow directly into the Segmentation Review Platform, a web application where archivists review, correct, and validate the automated labels before they enter the catalog.

Developed by the Vanderbilt Cloud Innovation Lab in partnership with the Vanderbilt Television News Archive and AWS, this open-source tool is designed to be domain-agnostic — equally effective on broadcast news, lectures, live events, sports, and any video collection waiting to be discovered.

Project Overview

This project consists of two integrated components: a backend pipeline that automatically segments video content using visual boundary detection, audio transcription, and AI classification; and a Segmentation Review Platform — a web application where archivists review, edit, and approve the pipeline's output before it enters the catalog. Together, they support configurable segment types and detection methods, making the system adaptable to any video domain.

Visual Data Algorithms

Black-frames

Step 1: Black Frame Detection (Worker)

Each 60-second chunk is analyzed for black frame runs using color histogram comparison:

1. Compute 32-bin color histogram for each frame (RGB channels)
2. Calculate chi-squared distance from a pure-black reference histogram
3. If distance < 0.3 → confirmed black frame
4. If distance < 8.0 → suspicious (may be very dark scene)
5. Refine coarse detections to frame-accurate start/end timestamps

For normal chunks, a coarse 1fps scan finds candidates, then a frame-by-frame refinement pass in ±2s windows determines precise boundaries. Short probe windows (≤15s) use frame-by-frame scanning directly.

Step 2: Event Extraction (Merger)

Black frame runs from all chunks are merged and converted into discrete "events":

1. Merge adjacent runs across chunk boundaries (gap < 0.1s)
2. Filter runs shorter than 0.1s (noise)
3. Extract events: runs separated by ≥15 seconds become distinct events
4. Remove events in first 5 minutes and last 60 seconds (margins)

Step 3: Segment Pairing (Merger)

Events are paired into segments using duration heuristics:

1. For each unpaired event, find the best partner where:
   - Duration is between 90s and 300s (1.5 to 5 minutes)
   - Duration is closest to a standard multiple of 30s
2. Remove "interior" events (black frames within paired segments)
3. Re-pair after cleanup
4. Probe for missing partners at standard offsets (30s, 60s, ..., 300s)
5. Short segments (<90s) → attempt to extend from endpoints
6. Final cleanup: merge overlaps, remove contained segments

Key Design Decisions

  • Configurable margin: Start/end margins are skippable (default: first 300s skipped for pre-content)
  • Histogram-based detection: More robust than simple pixel averaging — handles noise, compression artifacts, and near-black scenes
  • Standard duration matching: Segments are paired using expected duration multiples, providing a strong pairing heuristic
  • Active probing: When events can't be paired from the initial scan, targeted Lambda invocations search for missing partners at expected offsets
  • 60-second chunks: Balances Lambda execution time against parallelism and Step Functions event limits

Transition Detection (Profile-Based)

An alternative visual detection method for videos that don't have reliable black frames between segments. Instead of looking for black frames, this approach detects the absence of a persistent visual element (such as a ticker, logo, or overlay) by comparing frame regions against a precomputed color profile.

📊

Color Profile Matching

A precomputed HSV color histogram captures what a target region looks like during primary content. Each frame is compared against this profile using chi-squared distance.

✂️

Region Cropping

Only the target region of each frame is analyzed (configurable crop boundaries), making detection fast and focused on the most informative pixels.

⚡

Single-Pass Scan

Processes the entire video in one pass at configurable frame rate (0.5–1 fps), grouping consecutive dissimilar frames into segments.

🔄

Automatic Fallback

If profile-based detection finds zero segments (profile mismatch, different era), the system automatically falls back to the black-frame method.

How It Works

1. Crop each frame to the target region (e.g., bottom 25% of frame)
2. Convert to HSV and compute a 36×32×32 bin histogram
3. L1-normalize the histogram
4. Compare against the precomputed color profile using chi-squared distance
5. If distance > threshold → frame is "dissimilar" (non-content segment)
6. Group consecutive dissimilar frames into segments
7. Filter: remove short bursts (<10s), merge nearby segments (<60s gap)
8. Skip configurable margin at start and end

Per-Source Configuration

Each video source has its own detection profile stored in S3, configured via a JSON file:

{
  "SOURCE_A": {
    "crop_top_fraction": 0.75,     // Top of target region (75% down)
    "crop_bottom_fraction": 1.0,   // Bottom of target region (100%)
    "crop_left_fraction": 0.0,     // Full width
    "crop_right_fraction": 1.0,
    "chi_square_threshold": 0.35,  // Sensitivity
    "scan_fps": 0.5,               // Frames per second to sample
    "profile_key": "config/profiles/SOURCE_A_profile.npy"
  }
}

Threshold tuning: lower = fewer detections (less sensitive), higher = more detections (more false positives). The profile must match the era and visual style of the video content.

Building a Color Profile

Profiles are built from ground-truth-labeled videos. The profile builder:

1. Load ground truth CSV with labeled segments (content vs non-content)
2. For each "content" segment, extract frames from the target region
3. Compute HSV histograms for all content frames
4. Average all histograms into a single representative profile
5. Save as .npy file → upload to S3

The resulting profile represents "what the target region looks like during primary content." Frames that deviate significantly from this profile are classified as non-content segments.

Detection Routing

The video dispatcher automatically selects the detection method based on the video source:

Video uploaded → Dispatcher extracts source ID from filename
  → If source has a detection profile configured → Profile-Based Detection
    → If 0 segments found → Fallback to Black-Frame Detection
  → Otherwise → Black-Frame Detection (default)

Transcription & AI Segmentation

After visual boundaries are detected, the pipeline feeds that output into an AI-powered transcript segmentation system. This stage identifies individual content segments within the non-break portions of each video — determining where one story ends and another begins.

How It Works

1

Video Transcription

AWS Transcribe Lambda

Uploads trigger automatic transcription via AWS Transcribe, producing word-level timestamps for the entire video. Output: JSON with every word and its precise start/end time.

↓
2

Commercial Filtering

Python (filter_commercials.py)

Uses the _segments.json output from the Visual Segment Detector to remove all words that fall within detected break segments. Inserts [ BREAK ] markers as hard boundaries.

↓
3

AI Segmentation

Amazon Bedrock (Claude Sonnet)

The filtered transcript is sent to Claude via Pydantic AI. The model identifies content segment boundaries by detecting topic changes, speaker handoffs, and transitions. Returns structured segment data with verbatim first/last sentences.

↓
4

Timestamp Matching

Python (timestamp_matcher.py)

Maps the AI-identified segment boundaries (first/last sentences) back to precise video timestamps using the original word-level transcription data. Produces frame-accurate start/end times for each content segment. Output: ai_results/{video}_segments.json

↓
5

Sub-Segment Detection

Amazon Bedrock (Claude) + Python

Loads visual segments and AI segments, merges them into a unified timeline, and uses Claude to detect transition speech at content→break boundaries. Output: subsegment_results/{video}_with_subsegments.json

↓
6

Evaluation

Python (evaluation_metrics.py)

Compares predicted segments against human-annotated ground truth using frame accuracy, segment F1 at multiple IoU thresholds, boundary F1 at multiple tolerances, and normalized edit distance.

↓
7

Results Merger

Python + Boto3

Uses the sub-segment JSON as the authoritative timeline. Enriches content segments with titles from AI segmentation and full transcripts from the transcription bucket. Output: result/{video}.json

AI Segmentation Approach

The system uses Claude (via Amazon Bedrock) with a carefully crafted archival prompt that instructs the model to:

  • Respect hard boundaries: [ BREAK ] markers are absolute — no segment spans across them
  • Identify natural transitions: Speaker handoffs, topic changes, and shifts in focus
  • Extract verbatim sentences: First and last sentences of each segment are extracted word-for-word for precise timestamp matching
  • Maintain continuity: Panel discussions that shift topics stay as one segment; same-story coverage across speakers stays unified
  • Complete coverage: Every part of the transcript must be assigned to a segment with no gaps

Segmentation Review Platform

The Segmentation Review Platform is a web application built for archivists. Once the backend pipeline produces its automated labels, archivists use this tool to review results, correct errors, and approve final annotations before they enter the catalog. Built with React + TypeScript + Vite and deployed on AWS Amplify Gen 2.

Technology Stack

Framework: React 18 + TypeScript
Build: Vite
Hosting: AWS Amplify
Auth: Cognito (email login)
Storage: S3 via Amplify Storage
API: AppSync GraphQL

Key Pages

📹 Video Select

Archivists browse and search all available videos from S3 storage. Preview video metadata and processing status before selecting one for review.

🎬 Results Viewer

Displays the pipeline's automated segmentation on a color-coded interactive timeline. Archivists click segments to jump to that point in the video and verify accuracy against the actual content.

✏️ Edit Mode

Archivists enter edit mode to correct segmentation errors: drag timeline markers, inline-edit timestamps, change segment type labels, merge segments, or add new ones. Approved edits save back to S3 and flow into the catalog database.

Pipeline Cost & Performance

Per 1-hour video (backend pipeline only):
├── Visual detection (Lambda workers): free-tier or ~$0.035/10 videos           
├── Transcription (AWS Transcribe): ~$0.72, 3-5 min
├── AI Segmentation (Bedrock Claude): ~$0.60-$0.80, 2-4 min
└── Evaluation: ~$0.01, 30 sec
Total: ~$1.50, 6-10 minutes end-to-end (before archivist review)

Pipeline Stages in Detail

1

Video Dispatcher

Lambda (S3 trigger)

Extracts the source network from the filename, selects the appropriate detection method (black frame or profile-based), and launches parallel processing.

↓
2

Visual Detection (Parallel)

Step Functions + Worker Lambdas (OpenCV, Docker ARM64)

Each video is divided into 60-second chunks. Up to 800 concurrent workers scan for visual boundaries (black frames or color profile deviations). Merger Lambda collects results, pairs events into segments, and probes for missing partners.

↓
3

Transcription (Parallel)

AWS Transcribe (Lambda trigger)

Runs in parallel with visual detection. Produces word-level timestamps for the entire video.

↓
4

Readiness Gate → AI Classification

Amazon Bedrock (Claude Sonnet)

Once both visual segments and transcript are available, Claude identifies topic boundaries and classifies each content segment. A second pass detects transition speech (teasers) at segment edges.

↓
5

Results Merger → Review Platform

Lambda + S3 + DynamoDB

Merges all outputs into a unified JSON (titles, transcripts, timestamps, segment types). Writes to S3 and DynamoDB. Results appear automatically in the Segmentation Review Platform for archivist review.

Infrastructure Resources

S3 Buckets

Source videos (video/), intermediate outputs (segment_results/, ai_results/), and final merged results (result/).

DynamoDB

Three tables: chunk results, per-video segment records (video_name + timestamp), and evaluation metric summaries.

Lambda Functions

Containerized (Docker) on ARM64 (Graviton). Worker: 2GB RAM, 5 min timeout. Merger: 512MB, 15 min. AI Segmentation: 10GB, 5 min.

Step Functions

Standard workflow with nested Map states. Processes up to 800 chunks concurrently (20 videos × 40 chunks each).

Amazon Bedrock

Claude Sonnet for transcript classification, topic boundary detection, and teaser identification. Invoked via Lambda.

AWS Amplify

Hosts the Segmentation Review Platform (React). Provides Cognito authentication and AppSync GraphQL API for the archivist UI.

Serverless Deployment

The backend pipeline deploys as event-driven Lambda functions connected by S3 triggers. Each stage runs automatically when its input becomes available — no orchestration code needed beyond S3 notifications:

Upload video to S3
  → [S3 trigger] → Transcription Lambda (AWS Transcribe)
  → [S3 trigger] → Visual Segment Detector
    → [Readiness Checker] → AI Segmentation (Bedrock Claude)
      → ai_results/{video}_segments.json
        → [S3 trigger] → Sub-Segment Detector
          → subsegment_results/{video}_with_subsegments.json
            → [S3 trigger] → Results Merger
              → result/{video}.json → Segmentation Review Platform

End-to-End Data Flow

📤

1. Video Upload

Video files (.mp4) are uploaded to S3, triggering the backend pipeline automatically.

⚡

2. Visual Boundary Detection (Pipeline)

Step Functions fans out: up to 800 concurrent Worker invocations scanning for black frames in 60s chunks, or searching for distinctive visual features in selected regions of the video.

Merger Lambda collects results, pairs black frame events into segments, and probes for missing boundaries.

💾

3. Store Segment Results (Pipeline)

Detected visual segments written to S3 (segment_results/{video}_segments.json) and DynamoDB.

📝

4. Transcription & AI Segmentation (Pipeline)

Videos are transcribed (AWS Transcribe), break segments are filtered out, and Claude identifies individual content segment boundaries within the remaining speech. Output: ai_results/{video}_segments.json

🎯

5. Sub-Segment Detection (Pipeline)

Sub-Segment Detector loads visual and AI segments, merges them into a unified timeline, and detects transition speech at content→break boundaries. Output: subsegment_results/{video}_with_subsegments.json

🌐

6. Archivist Review (Segmentation Review Platform)

Archivists open the Segmentation Review Platform, select a video, view the pipeline's detected segments on an interactive timeline, and verify or correct any errors.

✅

7. Approval & Catalog Ingest

Archivist-approved annotations are saved back to S3 and written to the catalog database, making the video segments discoverable by researchers.
